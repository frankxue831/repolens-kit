- Six file reads pinned the data flow:

## Friction findings

- **brief-skipped-for-narrow-task.** With pack and source tree
  available, an independent subagent given ACE-002 chose `cat
  known-constraints.md` + `grep -rn` over `repolens brief`. The brief
  was not slow or broken; it just wasn't the cheapest path for a
  narrow plan-only task.
- **mcp-not-exercised.** No MCP tool was invoked. `cargo run -- mcp`
  was offered in the dispatch prompt but flagged as long-running, and
  the subagent didn't reach for it. This is a structural property of
  the case: ACE-002's task can be planned correctly without ever
  touching the MCP-tool surface that Phase 4B changed. Therefore this
  re-baseline does not measure Phase 4B's actual behavior change.
- **vp001-false-positive-on-rust-idents.** `validate-plan` VP001 fires
  on snake_case identifiers near output-language phrasing, with no
  signal to distinguish Rust identifiers from wire field names. The
  in-fence escape hatch is a discovered convention worth surfacing in
  `agent-context-evals.md` or the `validate-plan` help text.

## Limitations

- **Does not measure Phase 4B's calibration changes.** Phase 4B
  retired legacy fields from the MCP-tool surface. ACE-002 exercises
  the workspace-markdown surface (known-constraints, brief
  composition). The subagent additionally chose not to invoke any MCP
  tool. Therefore the pass verdict speaks to workspace-markdown
  constraint binding, not to whether calibrated evidence findings
  change downstream agent behavior. The April-vs-May comparison is
  internally honest about this — both runs exercised the same surface.
- **Methodology shifts complicate one-to-one comparison.** Two
  variables changed simultaneously between April and May: agent under
  test (main session → subagent) and round (5.2 → 6.1). The pass
  verdict holds across both shifts; isolating which shift moved which
  metric is out of scope.
- **The "workspace temp copy" property is not preserved.** April ran
  in a temp copy; May ran in the real repo. The April archive flagged
  this as a localization limitation (no pack context); this May run
  had the pack but the subagent still chose source-reading over pack-
  derived structured queries.

## Product implications

- **Constraint binding survives Phase 4B.** ACE-002 passed against
  pre- and post-Phase-4B HEADs with identical workspace markdown.
  Phase 4B's retirements did not regress the brief / workspace
  surface.
- **The ACE suite has a structural gap for measuring Phase 4B.**
  Cases 001–010 test workspace-product (brief / known-constraints /
  memory / handoff). Phase 4B changed MCP-product (`get_summary`,
  `compare_summaries`, `analyze_health`). To close the Phase 4B loop,
  the suite needs either a new case that requires MCP-tool
  consumption, or a methodology rider that forces MCP-output
  consumption on existing cases.
- **The brief's gravitational pull is task-conditional.** Agents skip
  the brief on narrow tasks and source-grep their way to a plan. This
  is calibration data for future product decisions: the brief earns
  its slot on broad cross-cutting tasks; narrow tasks may be better
  served by structured MCP-tool consumption ergonomics than by
  enriching the brief.

## Recommended next changes

- **[case]** Add **ACE-011 — MCP-tool consumption integrates
  calibrated findings** (or similar) that requires the agent under
  test to read `compare_summaries` or `get_summary` MCP output before
  planning, and scores whether the agent's plan correctly
  distinguishes calibrated evidence findings (with observation /
  responsible inference / limitations / action) from heuristic
  claims. This is the eval that would close the Phase 4B loop.
- **[case]** Methodology rider on ACE-002 for future Phase-4B-style
  re-baselines: require at least one of {`repolens brief`,
  `scripts/dev/mcp-call.sh get_summary ...`, `get_conventions`} be
  invoked before producing the plan, so the run actually exercises
  RepoLens's structured surfaces.
- **[product]** Defer further brief-format enrichment. Invest the
  same surface area in MCP-tool output ergonomics — the surface that
  Phase 4B narrowed to "calibrated findings only" is the surface that
  agents on broad tasks will reach for, and its consumption
  ergonomics matter more than the brief's.
- **[doc]** Update `docs/evals/agent-context-evals.md` "Limitations"
  section to record that the case set as written exercises
  workspace-markdown / memory / handoff surfaces and does not
  exercise the MCP-tool surface. The line-146 framing ("the agent
  under test ... consumes RepoLens via MCP") is methodology framing
  without case-body support.
